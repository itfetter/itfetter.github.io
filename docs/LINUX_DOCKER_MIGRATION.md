记录日期：2026-10-06。**这是用户确认保留的后续方案，尚未实现、构建镜像或部署。当前继续使用 Cloudflare Workers + D1 + R2。**

## 想迁移时先看这里

目标是在 Linux 云服务器上运行可拉取的应用镜像，用 Docker Compose 管理应用；数据库与图片独立于应用容器。宝塔可用于域名、HTTPS 和 Nginx 反向代理。单台服务器阶段不引入 Kubernetes。

```text
访客 → HTTPS / Nginx → 博客应用容器
                         ├─ 独立数据库：文章、草稿、历史、评论、留言、认证等
                         └─ 阿里云 OSS（或 R2）：图片文件
GitHub 代码 → CI 构建版本镜像 → 镜像仓库 → 云服务器拉取更新
```

镜像仓库可选 GitHub Container Registry 或阿里云容器镜像服务，实施时再决定账户、可见性与权限。当前没有已发布镜像地址、Dockerfile、Compose 配置或可直接执行的容器部署流程。

## 实施前需要开发什么

1. 将 Cloudflare Worker 的请求处理、静态资源和平台绑定适配为 Linux 可运行的后端，建议继续使用 Node.js；不能把现有 Worker 直接打包就认定能运行。
2. 增加数据库适配层。D1 当前基于 SQLite；宝塔中的 MySQL 不是替换连接地址就能兼容。数据库最终选型尚未确定，须处理 SQL、迁移、事务、触发器、唯一约束与并发语义，保留 id/version 检查和原子限速。
3. 增加图片存储适配层，支持阿里云 OSS，同时保留 R2 路径。上传校验、公开读取、备份和导入都需要适配，不能假定 OSS 与 R2 接口完全一致。
4. 保持同源 /admin/、/api/、/articles/<id>/ 和 /images/<key> 路由，优先由应用转发或映射 /images/ 到所选存储，保留文章正文已有引用。若改用图片域名，须同时处理公开正文、草稿与历史中的旧地址；不能只上传文件便宣称图片迁移完成。
5. 提供镜像构建与发布 CI、版本标签、Docker Compose 示例、环境变量示例、数据库升级与备份说明。继续支持现有 Cloudflare 部署，不提前替换线上架构。
6. 保留密码哈希、会话撤销、HTTPS Cookie、同源写请求检查、Markdown 清理、评论纯文本、回复关系和权限隔离。

## 镜像更新与持久化

代码更新后由 CI 测试并构建带版本号或提交 SHA 的镜像，再由服务器拉取并重建应用容器。数据库和 OSS 数据不随应用容器重建而删除。

数据库可使用独立服务，或单独数据库容器配持久化卷；备份应另存，不等同于持久化卷。不得将生产数据、数据库密码、OSS 密钥、真实配置或备份打入镜像、提交 GitHub。凭据通过服务器私有配置或秘密管理注入；OSS 权限限定必要桶与操作。

更新前备份，数据库结构按新增迁移升级，不修改已发布迁移。保留旧镜像用于回滚，但旧镜像不一定兼容升级后的数据库；需要兼容性检查与恢复方案，不能只靠切换镜像回退数据。不要执行会删除数据卷的清理操作。

## JSON 备份在迁移中的作用

当前后台 JSON 备份是内容迁移材料，不是完整运行环境或直接可导入 MySQL 的 SQL 文件。包含文章、草稿、分类、历史、私人留言、文章评论及回复关系，并包含备份范围内 R2 图片的 Base64、键名和类型。正文保存图片引用，图片文件还原到对应路径才能保持位置。外部 URL 引用只保存链接，不会自动抓取第三方图片。

当前格式为 itfetter-content-v1；便捷备份有数量和体积限制：内容约 400 万字符、图片合计 12 MB / 100 张，文章最多 1000、历史最多 5000、留言及评论各最多 1000。迁移前核对导出实际成功和各项数量；超过范围用 Cloudflare 原生 D1/R2 导出并另做转换，不能把便捷备份当成无限全库灾备。

现有恢复仅补缺，不覆盖已有数据，跨数据库与图片存储不保证事务。Linux/OSS 导入功能仍需实现，并保留先验证、回复依赖顺序、幂等补缺及失败重试行为。备份不含管理员密码、会话、密钥、部署配置、限速或访客去重记录，阅读统计不等于包含完整去重明细；在新服务器独立初始化管理员。文件含私人留言及访客邮箱，妥善保存。
